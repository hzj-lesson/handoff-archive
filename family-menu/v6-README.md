## 三分钟配好（只做一次）

| 步骤 | 做什么 |
|---|---|
| 1 | **你**打开链接 → 「设置」填她的楼栋门牌和电话（默认校区已是西华师范大学华凤校区二期） |
| 2 | 「🔔 通知设置」选推送方式、填 key → 保存 → 点「发一条测试」确认手机能收到 |
| 3 | 点「🔗 生成并复制链接」→ **微信发给她** |
| 4 | 她打开链接就是「宝贝的点单页」，地址和推送配置已自动带上 |

推送方式：**Server酱 Turbo**（`sct.ftqq.com` 扫码拿 SendKey，最省事）/ **PushPlus**（`pushplus.plus` 拿 token）/ **WxPusher**（需 appToken+UID）/ **Bark**（仅 iOS）/ **不推送**（她复制订单文字发你微信）。

> key 只写不读，存在链接里发给她；最坏情况是有人拿到后给你发垃圾推送，不影响账号安全。

## 她怎么用

选品类 → 选品牌 → 菜品右边点 `＋` → 挑规格 → 购物车点 **「💕 告诉 TA 我想吃」**。配了推送你微信秒收；没配就复制发你微信。

## 你这边

推送直接看微信消息；也可以把订单文字**粘贴进「📥 收单箱」**，点「✓ 已下单」标记。右上角可切换「我是 TA / 我是宝贝」两种视角。

## 技术说明

- **单个 HTML 文件，约 69KB，零依赖**，纯前端
- 数据存 `localStorage`（键 `naicha_order_v4`），不上传服务器
- 数据结构：`PRESET` = `[id, 名称, emoji, 品类, [[品名, 备注], …]]`；品类在 `CATS`，规格在 `SPECS`（**纯字符串，无价格**）
- **加品类**：`CATS` 加一项 + `SPECS` 加一套规格 + `PRESET` 里标品类，代码不用动
- **版本迁移**：`VER` + `migrate()`，数据版本低时自动合并新品牌，**保留用户关掉的品牌、自定义品牌、推送配置和地址**，并清掉旧价格字段
- 底部布局：`body` 留白 = 结算条 58px + 导航 52px；非点单页自动收窄（`body.no-bar`）

> ⚠️ 数据只存本地浏览器，换设备或清缓存会丢，重要订单先「导出备份」。
> 两台手机的数据不自动互相同步 —— 她点了什么靠推送/微信告诉你，这是刻意设计（免后端、免注册）。
